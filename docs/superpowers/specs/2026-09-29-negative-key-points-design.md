# 부정 리뷰 "주요 포인트" 키워드 설계

- 작성일: 2026-09-29
- 상태: 설계 승인(대화)

## 1. 배경

대시보드의 **부정 주요 키워드 TOP 5**는 규칙기반 분류기의 `matched_words`(감성사전 매칭 단어)를
집계한다. 실측(시트 898행) 결과 두 가지 문제가 있다.

1. 카카오·구글은 별점으로 즉시 판정해 `matched_words`가 비어 있다. 본문이 있는 부정 리뷰 48건
   (구글 42, 카카오 6)이 키워드 집계에서 전부 빠진다 — 불만이 가장 구체적인 리뷰들이다.
2. 네이버 부정 키워드도 "환자", "대상", "친절", "재방문"처럼 불만과 무관한 사전 단어가 상위에 온다.
   Claude가 감성을 재판정해도 `matched_words`는 규칙기반 결과 그대로다.

## 2. 목표

부정 리뷰마다 **그 리뷰의 가장 주요한 불만 포인트**를 1~2개 짧은 말로 기록하고(예: "주차",
"상담 태도", "시술 효과", "가격"), 부정 TOP 5를 이것으로 집계한다. 모든 채널 대상.

하지 않는 것: 긍정 TOP 5 변경, 유료 API 도입, 별점 판정(`method=="rating"`) 행의 감성 변경.

## 3. 설계

### 3.1 시트 컬럼
- `sheets_writer.HEADER` 끝에 `key_points`를 추가한다(쉼표 구분 문자열). 기존 컬럼 위치는 그대로.
- `ensure_header`: 시트 헤더가 새 HEADER의 **앞부분과 정확히 일치하고 뒤 컬럼만 없는 경우**,
  빠진 헤더 셀을 한 번의 호출로 채운다. 그 밖의 불일치는 지금처럼 예외. 이 덕분에 코드 푸시와
  시트 헤더 변경의 순서를 맞출 필요가 없다(새 코드가 처음 실행될 때 스스로 확장).
- `review_to_row`: 새 행의 `key_points`는 빈 값.

### 3.2 재분류 단계 확장 (`reclassify.py`)
- 후보에 `tasks` 필드를 둔다.
  - `method=="lexicon"` → `["sentiment", "key_points"]` (기존과 같이 감성 판정 + 부정이면 주요 포인트)
  - 그 외, `sentiment=="부정"`이고 본문이 있고 `key_points`가 빈 행 → `["key_points"]` (감성은 건드리지 않음)
- 요청 파일에 `existing_key_points`(지금까지 쓴 포인트와 건수)를 넣어 같은 불만은 같은 말로 쓰게 한다.
- 결과 항목: `sentiment`/`confirmed`는 `sentiment` 작업일 때만, `key_points`(문자열 리스트)는
  최종 판단이 부정일 때 쓴다. 구체적 포인트를 찾을 수 없으면 `["-"]`로 적는다(다시 후보로 나오지
  않게 하고, 대시보드는 `-`를 집계하지 않는다).
- 반영: 후보의 작업 종류에 맞는 행(감성 작업은 아직 lexicon인 행, 포인트 작업은 부정이고
  `key_points`가 빈 행)만, 같은 실행에서 이미 쓴 행은 빼고 시트 순서대로 매칭한다. 모든 갱신을
  `batch_update` **한 번**으로 보낸다(Sheets 쓰기 quota).
- `--export`도 `ensure_header`를 호출한다.

### 3.3 대시보드 (`index.html`)
- `toReview`가 `key_points`를 `keyPoints` 배열로 읽는다(`-` 제외).
- 부정 TOP 5는 `keyPoints`로, 긍정 TOP 5는 기존 `keywords`(`matched_words`)로 집계한다.
- 키워드 카드 아래 설명 문구를 바꾼다.

### 3.4 문서
- 폴더 `CLAUDE.md`의 요청/결과 형식과 판단 기준에 주요 포인트 작성 규칙을 추가한다.

## 4. 주요 포인트 작성 규칙 (Claude)
- 1~2개, 각 2~8자 정도의 명사구. 리뷰가 가장 강하게 불만을 말한 것부터.
- `existing_key_points`에 같은 뜻이 있으면 그 표현을 그대로 쓴다.
- 병원이 개선에 쓸 수 있는 단위로 쓴다("불친절"보다 "상담 태도"/"접수 응대"처럼 대상이 드러나게,
  단 본문이 그 이상을 말하지 않으면 "불친절"도 허용).
- 본문에 없는 내용을 추측하지 않는다. 판단 근거가 없으면 `["-"]`.

## 5. 테스트
- `ensure_header`: 앞부분 일치 시 뒤 컬럼 확장(1회 호출), 그 밖 불일치는 예외.
- `find_candidates`: lexicon → 두 작업, 부정+본문+포인트 없음 → 포인트 작업, 이미 포인트가 있거나
  본문이 없으면 제외, `existing_key_points` 집계.
- `apply_results`: 포인트만 쓰는 결과, 감성+포인트, 같은 본문 여러 행, batch_update 1회.
- 대시보드: 로컬 서버로 열어 부정 TOP 5가 `key_points`로 나오는지 확인.

## 6. 배포·검증
- 푸시 후 `reclassify.py --export`가 헤더를 확장하고 기존 부정 리뷰 전체를 후보로 낸다 →
  Claude 판단 → `--apply` → 다시 export했을 때 후보 0건, 대시보드 부정 TOP 5 확인.
